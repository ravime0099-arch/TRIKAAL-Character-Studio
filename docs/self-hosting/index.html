#Self-hosting

Ara 3D Gen runs entirely on your machine: in the browser, or headless from the command line. It works on Windows, macOS and Linux, and needs Node 20+ and git. The app runs in any current Chrome, Edge, Firefox or Safari.

#Install

git clone --depth 1 https://github.com/olatunde85/3d-gen.git
cd 3d-gen
npm install
npm run setup-assets   # one-time: downloads CC0 MakeHuman data (~420 MB), builds public/assets (~50 MB) and fetches the site videos
npm run dev            # open http://localhost:5173 (landing page; the app is at /app/)

--depth 1 downloads only the current files (about 50 MB) instead of the full history; drop it if you want every past commit, or run git fetch --unshallow later.

On Windows, run the same commands in PowerShell, Command Prompt or Git Bash.

#Update an existing clone

git pull
npm install            # picks up any new or updated dependencies
npm run setup-assets   # rebuilds public/assets; reuses the data already downloaded, so it takes about a minute
npm run dev

Re-run setup-assets after every update. New versions can add or change generated assets (for example new eye colours), and the app falls back to the old ones until you do. If you have local changes, commit or stash them before git pull. Each release lists what changed.

#Build and deploy

npm run build          # -> dist/: landing page at /, the app at /app/, Studio at /studio/, Play at /play/, the developers page at /developers/, Terms at /terms/, Privacy at /privacy/, these docs at /docs/, videos at /media/

Set BASE_PATH=/sub/path/ when hosting under a sub-path, such as GitHub Pages.

Site videos (media/ara-play-promo.mp4 and media/ara-studio-reel.mp4) are kept out of git, in the repository's media release, so re-rendering them never grows the repository. scripts/media.json records which version the site uses, and the build downloads any missing video into public/media/ and checks it (npm run media:fetch). Set ARA_SKIP_MEDIA=1 to build without them; the pages then show the posters.

The Terms (terms/index.html) and Privacy Policy (privacy/index.html) name the operator of ara3dgen.com and its contact address. If you host your own copy, put your own details in them.

The whole site is static files, and all the character work runs in each visitor's browser, so free static hosting scales with traffic. ara3dgen.com runs as a Cloudflare Worker that serves dist/ as static files, and static-file requests are free and unmetered. wrangler.site.jsonc sets it up: change its name and routes to your own Worker and domain, run npx wrangler login once, then npm run deploy:site, which builds the whole site, checks that dist/ has every part of it (pages, docs, schemas, media) and only then deploys. dist/ holds about 1,700 files, more than the dashboard's 1,000-file upload accepts, so it deploys with Wrangler. Any other static host works too. Cache headers come with the build (_headers). A first visit to the builder downloads about 7 MB (the body shapes its first character uses, its clothes and full-size images), and the browser caches it after that.

#Command line

Generate characters without opening a browser, for batch jobs, CI or asset pipelines. Outside this repository, use npx ara3d, which needs no clone. Inside it:

npm run export -- --preset "The Soldier" --detail high --out out
npm run export -- --random 42 --formats glb,fbx
npm run export -- --params my.params.json          # regenerate from a saved params.json
npm run export -- --all-presets --out out

Every exported zip includes the character's params.json, so any character can be regenerated or tweaked later.

#Tests

npm test            # builds 259 characters and validates every export format
npm run test:gltf   # exports GLBs, loads them with three.js in headless Chrome, checks every bone of every clip
npm run test:studio:model # validates Studio recipes and timeline continuity
npm run test:studio # Studio browser flows and real MP4 encoding
npm run test:ui     # drives the app in headless Chrome: build, slider, preset, animation browser, export

test:gltf, test:ui and test:studio need Chrome, Chromium or Edge (set CHROME=/path/to/browser if it isn't found). The scripts/blender_*.py scripts import exports into Blender and render previews; Blender is optional.

#Motion capture data

The motion-captured clips are baked into src/core/anim/clips/mocap-data.ts, which is committed, so you don't need the source recordings. To change them, edit scripts/mocap-takes.ts, run npm run setup-assets (it downloads the takes into vendor/mocap/cmu), then npm run build-mocap. See Animations.

#Studio

Studio needs no server API or API key: sets, music, sound effects, recording and voice effects all run in the browser. Microphone recording and video export need HTTPS or localhost.

Serving it: the build ships the compressed music in media/music/ and the sound effects in media/effects/, each with its credits. Serve .mp3 as audio/mpeg, .wasm as application/wasm and .mjs as JavaScript. Every file is under Cloudflare Pages' 25 MiB limit.

The speech model: typed dialogue downloads the Supertonic 2 model (about 265 MB) from Hugging Face the first time it's used, pinned to revision 75e6727618a02f323c720cba9478152d4bc16ca4 of Supertone/supertonic-2. It isn't part of the build. To serve it yourself, copy that model directory to a CORS-enabled host (object storage or a model host), keep its licence with it, and set VITE_STUDIO_TTS_MODEL_URL before building. The directory needs:

  • onnx/tts.json and onnx/unicode_indexer.json
  • onnx/duration_predictor.onnx, text_encoder.onnx, vector_estimator.onnx and vocoder.onnx
  • voice_styles/F1.json, F2.json, M1.json and M2.json

The speech runtime (about 14 MiB, single-threaded, no cross-origin isolation headers needed) loads only when speech is generated. The character builder and normal Studio playback never load it.

Rebuilding music and sound effects: the compressed files are committed, so a normal build doesn't need the originals or FFmpeg. To regenerate them, install FFmpeg, put the original recordings in music-for-ara/ and sound-for-ara/ at the project root (they aren't kept in the repository), then run npm run build:studio-music or npm run build:studio-effects. Music is loudness-matched (about −20 LUFS) and compressed to MP3; effects are compressed without trimming.

Studio tests:

npm run test:studio:model         # project format, validation, timelines and seating
npm run test:parcel               # ordinary held-parcel movement, two-hand contact, unchanged gait, clearance and release state
npm run test:animations           # animation poses, recovered landings, recorded gait layers and parcels on 18 bodies/rigs/binds
npm run test:studio               # every set, the editor, Assist, recovery, MP4 export and the builder round trip
npm run test:studio -- --new-project # fresh projects, save-first downloads, recordings, Undo and mobile controls
npm run test:studio -- --cast     # five characters, arrangements, framing and an MP4 with music
npm run test:studio -- --sfx      # sound-effect timing, mixing, editing and export
npm run setup:studio-speech       # caches the speech model once, for the next suite
npm run test:studio -- --audio    # voice effects, music, real speech generation, recording and bundles
npm run test:keys                 # your own AI and voice keys: every provider and error, against a local stand-in
npm run test:keys:browser         # Keys, Assist writing, Ask Ara and Sound voices in a real browser, against the stand-in

Screenshots and videos from the browser suites are saved in out/studio-expansion/. --audio uses a simulated microphone; set STUDIO_TTS_FIXTURE to use a model directory you already have.

#Rebuild the Studio reel

The home page plays media/ara-studio-reel.mp4 and the README shows it as a GIF. Both are cut from the films in src/studio/examples/reel.ts (the same films Studio's Assist offers as examples). To regenerate them after changing a film, install FFmpeg and a supported browser, then run:

npm run test:studio -- --reel
npm run build:studio-reel

The first command renders each film with Studio's MP4 export, plus a screenshot of the editor, to out/studio-expansion/; REEL_SCENES=2,5 renders only those films. The second keeps the part of each film listed in REEL, speeds it up slightly, joins the films with short crossfades and the music, and ends by zooming out into the editor. It writes the MP4 and its poster to public/media/, and a silent GIF of it for the README to docs/media/ara-studio-reel.gif. Run npm run media:publish to upload the new video to the media release and record it in scripts/media.json, then commit that file.

The Ara Play section plays media/ara-play-promo.mp4, just under a minute of Dead Drop, a demo campaign kept in scripts/promo/dead-drop.json. To regenerate it:

ARA_TEST_NATIVE_GPU=1 npx tsx scripts/play-browser-check.ts --promo
npm run build:play-promo

The first command plays each shot in the real game in Chrome, with bots driving the hero, and records it at 4K to out/promo/; PROMO_SHOTS=rescue,city records only those shots. The second cuts them to the timeline in scripts/build-play-promo.ts, with captions, transitions, the game's own music and an end card, and writes a 1080p video and its poster to public/media/, plus a 1440p master for uploading to video sites at out/play/ara-play-promo-master.mp4. Publish the new video with npm run media:publish and commit scripts/media.json.

Vehicle validation: npm run test:vehicles checks fitting across body shapes, rigs and bind poses and loads animated GLB/FBX props through real importers. npm run test:studio -- --vehicles exercises vehicle controls, recovery, deterministic scrubbing and GPU disposal, and writes visual reviews under out/vehicles/. Vehicles use local procedural geometry; they require no external downloads.

Additional sound-effect originals can be kept in new-sound-effects/ and newer-sound-effects/. Run npm run build:studio-effects to create the optimized MP3 assets declared in src/studio/audio/effects-catalog.ts. Existing shipped effects are retained when their original WAVs are absent. Only the optimized files under public/media/effects are deployed.
